# Диагностика TLS GigaChat в Bothost

## Что подтверждено кодом

- OAuth используется по адресу `ngw.devices.sberbank.ru:9443/api/v2/oauth`.
- API модели используется по адресу `api.giga.chat/v1/chat/completions`.
- Проверка TLS включена. `verify=False` и `CERT_NONE` не используются.
- Клиент использует системное хранилище через `truststore`; при заданном
  `GIGACHAT_CA_BUNDLE` Requests дополнительно получает путь к CA bundle.
- Текущий `python:3.11-slim` Dockerfile не устанавливает сертификаты НУЦ
  Минцифры явно.

Официальная документация GigaChat указывает, что для OAuth и API требуется
корневой сертификат Минцифры, а при его отсутствии возможна ошибка
`CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain`:

https://developers.sber.ru/docs/ru/gigachat/certificates

Это делает отсутствие CA основной гипотезой, но прежний журнал сохранил только
тип `SSLError`. Без диагностического запуска в том же контейнере нельзя
исключить DNS, таймаут, сетевой фильтр или TLS-прокси Bothost.

## Безопасная проверка

Проверка конфигурации без сети:

```bash
python check_gigachat_tls.py
```

Проверка DNS и TLS-handshake с обоими публичными endpoint:

```bash
python check_gigachat_tls.py --network
```

Команда не выполняет OAuth, не передаёт ключ авторизации и не вызывает модель.
Она не отключает проверку сертификатов. В выводе нет `.env`, токенов или
заголовков авторизации.

## Как интерпретировать результат

- `SSLCertVerificationError`, `verify_code=19` или сообщение про
  `self-signed certificate in certificate chain` подтверждает отсутствие
  требуемой цепочки доверия. После этого в образ нужно добавить официальные
  корневой и выпускающий сертификаты для Linux и выполнить
  `update-ca-certificates` либо передать проверенный bundle через
  `GIGACHAT_CA_BUNDLE`.
- `gaierror` означает проблему DNS; установка CA её не исправит.
- `TimeoutError` указывает на маршрутизацию, firewall или недоступность порта.
- `OK` для обоих endpoint означает, что TLS-цепочка уже доверена; тогда нужно
  исследовать следующий HTTP/OAuth-ответ, не меняя сертификаты.

Не следует скачивать сертификаты из случайных источников, использовать
`verify=False` или добавлять сертификат без проверки официального источника и
отпечатка.

## Проверка после будущего исправления

После пересборки образа команда с `--network` должна вернуть `OK` для:

- `ngw.devices.sberbank.ru:9443`;
- `api.giga.chat:443`.

Только после этого отдельно выполняется один разрешённый OAuth/модельный тест и
проверяется журнал автоматического цикла. Локальный успех не подтверждает
работоспособность сети Bothost.
